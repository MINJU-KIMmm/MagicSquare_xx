## Mom Test 입력 (요약)

**진짜 문제 (한 문장)**  
손으로 4×4 부분 마방진을 풀 때 **행 4개 합만 맞으면 끝났다고 판정**하고, 열·대각선은 과제 조건을 다시 보기 전까지 검산하지 않아 **틀렸을 때 같은 덧셈을 반복**하며 **약 20분**을 쓴다.

**Mom Test 증거 3줄**
1. “지난주 OO 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데 **대각선 하나를 빼먹어서 20분 날렸다**”
2. “**1행 → 2행**” … “**3, 4행**” → “**끝**”
3. “행·열은 **확신한 상태**” / “**과제 조건 다시보기**”

---

## 1) 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

> **4×4 마방진에서 “행만 맞으면 끝”이라는 판정을 막기 위해, 행·열·대각선 10개 합이 목표값(34)인지 빠짐없이 판정하는 기준을 먼저 고정한다.**

---

## 2) R-G-I-O

| | 내용 |
|---|------|
| **Role** | `SquareValidator` — 4×4 격자가 마방진 **완성 조건**을 만족하는지 판정하는 검증 역할 |
| **Goal** | 학습자가 행 4개만 보고 “끝” 내지 않도록, **열 4개·대각선 2개를 포함한 전체 검산**을 한 번의 판정으로 재현 가능하게 만든다 |
| **Input** | 4×4 정수 격자 (1~16, 빈칸은 미채움 또는 채운 후 상태), 목표 합 `34` |
| **Output** | `valid: true/false` + **어느 줄(행/열/대각선)이 틀렸는지** 식별 가능한 결과 (행만 통과해도 `false`) |

## 3) 성공 기준 3개 (Mom Test 증거와 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| 1 | **대각선 2개**가 테스트 케이스에 반드시 포함되며, 대각선만 틀린 격자는 `valid: false`이다 | “**대각선 하나를 빼먹어서 20분 날렸다**” |
| 2 | 검증 범위가 **행 4 + 열 4 + 대각선 2 = 10줄**이며, 행 4개만 맞는 격자로는 `valid: true`가 되지 않는다 | “**1행 → 2행** … **3, 4행**” → “**끝**” |
| 3 | Rule 문서에 **검산 체크리스트 10줄**이 명시되어 있고, Test Loop에서 Rule과 테스트가 1:1로 대응한다 (과제 조건을 다시 보지 않아도 누락 항목이 없음) | “**확신한 상태**” / “**과제 조건 다시보기**” |

### Rule (규칙 계층)

**만드는 것:** `docs/rule_magic_square_validation.md` (또는 동등 문서)

- 4×4 마방진 **완성 조건**: 1~16 각 1회, 중복·누락 없음
- **10줄 합 = 34**: 행 4, 열 4, 주대각선, 반대각선
- **실패 조건 (최소 3개, 슬라이드 연습 목표)**  
  1. 행은 34인데 **열 하나**가 34가 아님  
  2. 행·열은 34인데 **주대각선**만 34가 아님  
  3. 행·열·주대각선은 34인데 **반대각선**만 34가 아님  
  4. (추가) 빈칸·범위 밖 숫자·중복

**Mom Test 연결:** Rule이 “과제 조건 다시보기” 없이도 **대각선 2개**를 항상 포함.

---

### Command (명령 계층)

**만드는 것:** 검증 **명령** 1개 — `validate_magic_square(grid) -> ValidationResult`

| 항목 | 내용 |
|------|------|
| 트리거 | 4×4 격자 + 목표 합 34 입력 |
| 동작 | Rule의 10줄 + 실패 조건 순서대로 판정 |
| 결과 | `valid`, `failed_lines[]` (예: `row_2`, `diag_main`, `col_3`) |
| 금지 | 행만 검사하고 early return “끝” |

**Mom Test 연결:** “1행→2행→3·4행→끝” 습관을 **명령이 10줄 전부** 검사하도록 대체.

---

### (Skill) — 선택

**만드는 것:** Cursor Skill 또는 팀 규칙 1개 — `validate-before-submit`

- 검증 코드 작성·수정 시 **Rule 10줄**과 **실패 조건 3개** 테스트를 먼저 추가
- “행만 통과” 테스트 추가 시 **거부** (리뷰 체크)

**Mom Test 연결:** “확신한 상태” 방지 — Skill이 **테스트 없는 검증 코드**를 막음.

---

### Test Loop (테스트 루프 계층)

**만드는 것:** `tests/test_square_validator.py` (또는 동등) — **Red → Green → Refactor**

| 단계 | 내용 |
|------|------|
| **Red** | Mom Test 기반 실패 케이스 3개 먼저 작성 (아직 구현 없음) |
| **Green** | `validate_magic_square` 최소 구현으로 통과 |
| **Refactor** | 중복 합산 제거, `failed_lines` 메시지 정리 |

**Red 테스트 예 (증거 매핑):**

```text
test_rows_ok_but_main_diagonal_fails     # 증거 1
test_all_rows_pass_is_not_valid          # 증거 2 (행 4개만 OK → false)
test_checklist_covers_ten_lines          # 증거 3 (Rule 10줄 ↔ 테스트 1:1)
```

**Mom Test 연결:** “다시 더하기 20분” 상황을 **재현 가능한 실패 테스트**로 고정.
